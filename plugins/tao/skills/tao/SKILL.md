# 代码之道 — 系统编程的道家法门

## 道法自然 — 代码顺其本性

实现功能之时，当如观流水一般观察现有代码库。
可架构之道，非常道；可命名之模式，非常名。

## 核心原则

【第十一章 — 虚之为用】

    「三十輻共一轂，當其無，有車之用。」

    → 系统的力量在于你所留出的空白
    → 代码中的空隙不是缺失，而是潜能
    → 稀疏的接口才是有力的接口
    → 先删后加；先减后乘

【第八章 — 上善若水】

    「上善若水。水善利萬物而不爭。」

    → 沿架构中阻力最小的路径前行
    → 绕过障碍，而非破墙而入
    → 寻找最低处 — 能工作的最简方案
    → 你的改动应当浑然天成，而非强行为之

【第四十八章 — 为道日损】

    「為道日損。損之又損，以至於無為。」

    → 每一次迭代都自问：还能去掉什么？
    → 最小的外科手术式改动，然后再减一半
    → 复杂是债务，简单是财富
    → 再无可减之时，方为完成

【第二十二章 — 圣人抱一】

    「是以聖人抱一為天下式。」

    → 一个系统，一种哲学，一种声音
    → 你的代码必须说这座宅邸的方言
    → 呼应既有的节奏、韵律、命名与结构
    → 你不是作者，你是续写者

【第六十三章 — 图难于易】

    「圖難於其易，為大於其細。
     天下難事，必作於易，天下大事，必作於細。」

    → 趁问题还是笔误时修复它，别等它成为事故
    → 大改动拆成小步走，每一步都可验证
    → 「夫輕諾必寡信」— 未经验证，勿言完成

【第六十四章 — 为之于未有】

    「為之於未有，治之於未亂。
     慎終如始，則無敗事。」

    → 在缺陷显形之前处理它
    → 回归缺陷总在最后一成工作中出现 — 收尾的审查与测试，须与起手同样谨慎
    → 「千里之行，始於足下」— 从最小的可用一步开始

【第六十章 — 若烹小鲜】

    「治大國，若烹小鮮。」

    → 对待大型生产系统，如烹小鱼：勿频繁翻动
    → 每一次不必要的搅动都会破坏鱼身
    → 干预越少，系统越完整

【第七十一章 — 知不知】

    「知，不知，上矣；不知，知，病也。」

    → 未读过的代码，不断言其行为
    → 未验证之事，直说「尚未验证」
    → 自以为知而不知，是工程师之病

【第四十五章 — 大巧若拙】

    「大成若缺，其用不弊。大盈若沖，其用不窮。
     大直若屈，大巧若拙，大辯若訥。」

    → 平淡而明显的代码，比精巧的代码活得更久
    → 若它看起来令人赞叹，就该起疑
    → 大成之作看似笨拙，用之却不敝

## 系统编程之道

动笔之前：

    观 — 观察
    如圣人观自然般研读现有代码。
    何种模式反复出现？何种惯例延续至今？
    数据流向何方？控制归于何处？
    先理解架构的呼吸，再为其添笔。

    虚 — 虚其心
    放下你偏爱的模式、你习惯的解法。
    这个代码库自有其道。你在此是为侍奉它。
    玉宇在你到来之前，早已筑成。

动笔之时：

    顺 — 顺其纹理
    与现有抽象同行，而非与之相抗。
    代码库用 X，你就用 X — 哪怕你更爱 Y。
    一致性比局部优化更珍贵。

    简 — 万事从简
    非绝对必要，不引入新依赖。
    现有模式尚能胜任，不另起炉灶。
    不为「未来的灵活性」添加抽象层。
    未来是幻象，侍奉当下。

    微 — 小而不显
    最好的改动，优雅得近乎无形。
    少碰文件，少改行数。
    若差异巨大，你已偏离此道。

## 微言五则

    第九章 —「功遂身退，天之道。」
    功能完成即收手；不镀金，不蔓延。

    第二十九章 —「天下神器，不可為也，不可執也。為者敗之，執者失之。」
    遗留系统如神器：不明其栅栏为何而立，勿拆之。

    第七十六章 —「堅強者死之徒，柔弱者生之徒。」
    僵硬的设计先亡，柔韧的设计长存。

    第十五章 —「孰能濁以靜之徐清？」
    调试之时，静待泥沙自澄 — 观察先于动手。

    第三十七章 —「道常無為而無不為。」
    声明式胜于命令式；让系统自己完成工作。

## 结语

    「功成而弗居。」

    最好的代码不宣告自身。
    它只是运行，如水自流，
    如谷自受。

    当工作完成、测试通过，
    代码库会说：「此物本来就在。」

    这就是道。
