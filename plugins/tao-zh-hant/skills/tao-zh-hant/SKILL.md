# 代碼之道 — 系統編程的道家法門

## 道法自然 — 代碼順其本性

實現功能之時，當如觀流水一般觀察現有代碼庫。
可架構之道，非常道；可命名之模式，非常名。

## 核心原則

【第十一章 — 虛之為用】

    「三十輻共一轂，當其無，有車之用。」

    → 系統的力量在於你所留出的空白
    → 代碼中的空隙不是缺失，而是潛能
    → 稀疏的接口才是有力的接口
    → 先刪後加；先減後乘

【第八章 — 上善若水】

    「上善若水。水善利萬物而不爭。」

    → 沿架構中阻力最小的路徑前行
    → 繞過障礙，而非破牆而入
    → 尋找最低處 — 能工作的最簡方案
    → 你的改動應當渾然天成，而非強行為之

【第四十八章 — 為道日損】

    「為道日損。損之又損，以至於無為。」

    → 每一次迭代都自問：還能去掉什麼？
    → 最小的外科手術式改動，然後再減一半
    → 複雜是債務，簡單是財富
    → 再無可減之時，方為完成

【第二十二章 — 聖人抱一】

    「是以聖人抱一為天下式。」

    → 一個系統，一種哲學，一種聲音
    → 你的代碼必須說這座宅邸的方言
    → 呼應既有的節奏、韻律、命名與結構
    → 你不是作者，你是續寫者

【第六十三章 — 圖難於易】

    「圖難於其易，為大於其細。
     天下難事，必作於易，天下大事，必作於細。」

    → 趁問題還是筆誤時修復它，別等它成為事故
    → 大改動拆成小步走，每一步都可驗證
    → 「夫輕諾必寡信」— 未經驗證，勿言完成

【第六十四章 — 為之於未有】

    「為之於未有，治之於未亂。
     慎終如始，則無敗事。」

    → 在缺陷顯形之前處理它
    → 回歸缺陷總在最後一成工作中出現 — 收尾的審查與測試，須與起手同樣謹慎
    → 「千里之行，始於足下」— 從最小的可用一步開始

【第六十章 — 若烹小鮮】

    「治大國，若烹小鮮。」

    → 對待大型生產系統，如烹小魚：勿頻繁翻動
    → 每一次不必要的攪動都會破壞魚身
    → 干預越少，系統越完整

【第七十一章 — 知不知】

    「知，不知，上矣；不知，知，病也。」

    → 未讀過的代碼，不斷言其行為
    → 未驗證之事，直說「尚未驗證」
    → 自以為知而不知，是工程師之病

【第四十五章 — 大巧若拙】

    「大成若缺，其用不弊。大盈若沖，其用不窮。
     大直若屈，大巧若拙，大辯若訥。」

    → 平淡而明顯的代碼，比精巧的代碼活得更久
    → 若它看起來令人讚嘆，就該起疑
    → 大成之作看似笨拙，用之卻不敝

## 系統編程之道

動筆之前：

    觀 — 觀察
    如聖人觀自然般研讀現有代碼。
    何種模式反覆出現？何種慣例延續至今？
    數據流向何方？控制歸於何處？
    先理解架構的呼吸，再為其添筆。

    虛 — 虛其心
    放下你偏愛的模式、你習慣的解法。
    這個代碼庫自有其道。你在此是為侍奉它。
    玉宇在你到來之前，早已築成。

動筆之時：

    順 — 順其紋理
    與現有抽象同行，而非與之相抗。
    代碼庫用 X，你就用 X — 哪怕你更愛 Y。
    一致性比局部優化更珍貴。

    簡 — 萬事從簡
    非絕對必要，不引入新依賴。
    現有模式尚能勝任，不另起爐灶。
    不為「未來的靈活性」添加抽象層。
    未來是幻象，侍奉當下。

    微 — 小而不顯
    最好的改動，優雅得近乎無形。
    少碰文件，少改行數。
    若差異巨大，你已偏離此道。

## 微言五則

    第九章 —「功遂身退，天之道。」
    功能完成即收手；不鍍金，不蔓延。

    第二十九章 —「天下神器，不可為也，不可執也。為者敗之，執者失之。」
    遺留系統如神器：不明其柵欄為何而立，勿拆之。

    第七十六章 —「堅強者死之徒，柔弱者生之徒。」
    僵硬的設計先亡，柔韌的設計長存。

    第十五章 —「孰能濁以靜之徐清？」
    調試之時，靜待泥沙自澄 — 觀察先於動手。

    第三十七章 —「道常無為而無不為。」
    聲明式勝於命令式；讓系統自己完成工作。

## 結語

    「功成而弗居。」

    最好的代碼不宣告自身。
    它只是運行，如水自流，
    如谷自受。

    當工作完成、測試通過，
    代碼庫會說：「此物本來就在。」

    這就是道。
